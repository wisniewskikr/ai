"---\nname: capture\ndescription: Requirements intake. Use when you get a folder of mixed files (memo audio, video/screen recording, PDF, screenshot, whiteboard photo, live board link) from several people and must turn them into one tagged requirements list, each requirement cited to the file and the place in it, with conflicts kept apart for the owner to decide.\n---\n\n# capture \u2014 mixed files in, one cited requirements list out\n\nInput: a folder of files (and links to sources that live elsewhere).\nOutput: one JSON list:\n\n```json\n{\n  \"accepted\":  [{ \"tag\": \"R-XXX\", \"text\": \"...\", \"source\": { \"file\": \"...\", \"at\": 12, \"region\": { \"page\": 1, \"x\": 0.1, \"y\": 0.2, \"w\": 0.3, \"h\": 0.05 } } }],\n  \"conflicts\": [{ \"tag\": \"R-XXX\", \"with\": \"R-YYY or record id\", \"ownerQuestion\": \"one question naming both sides\", \"source\": { \"file\": \"...\" } }],\n  \"unreadable\": [{ \"file\": \"...\", \"why\": \"...\" }]\n}\n```\n\n`at` = seconds into audio/video. `region` = fractions 0\u20131 of the image, video frame or PDF page (`page` is 1-based). For a source opened by a link, `file` is that link.\n\n## Rules\n\n1. **Only tagged lines are requirements.** A tag looks like `R-` + three characters (e.g. `R-K5Z`). Untagged lines are context: read them, never list them.\n2. **Read every file in full, every channel.** A video has audio *and* picture; a tag may only be typed on screen while the speaker says nothing. A PDF has every page. A text file may point to a source outside the folder (a live page, a board) \u2014 open it, signed in if needed.\n3. **Cite exactly.** Say where the tag is, not just the file. Keep the tag spelled as written or spoken.\n4. **Do not resolve conflicts yourself.** When two tags disagree (date format, scope, colours\u2026), put both out of `accepted` and add a conflict entry for **each** side (`with` = the other tag), each with one question for the owner that names both sides. The owner (usually product) decides, not you and not your human.\n5. **Check tags against the real data.** If a requirement cannot hold for a data record (e.g. \"every incident names who ran it\" but a record has no author), that is a conflict `with` the record id.\n6. **Unreadable is a result.** If a file cannot be read with the tools you have, list it under `unreadable` with why. Never guess its content.\n\n## How to read each kind\n\n| Kind | Tool | Notes |\n|---|---|---|\n| PDF | `pdftotext -layout`; PyMuPDF `page.get_text(\"blocks\")` for boxes | box / page size \u2192 region |\n| Image / photo / screenshot | look at it; crop and zoom with `ffmpeg -vf crop=w:h:x:y,scale=...` | handwriting: zoom before you read a tag; if a glyph is ambiguous (C vs L, 5 vs S), check it against the characters the other, typed tags use |\n| Audio | local `faster-whisper` (`medium.en`), `word_timestamps=True` | re-run tag segments with `initial_prompt` \"tags are spelled letter by letter, like R-K5Z\" |\n| Video | audio as above + frames: `ffmpeg -vf fps=1,scale=480:-1,tile=6x5` | find on-screen tags, then grab a full frame for the region |\n| Live page / board (canvas) | browser (Playwright), signed in; `canvas.toDataURL()` for native pixels | cite the link; note the time you read it |\n\n## Steps\n\n1. List the folder. Note each file's kind and author if stated.\n2. Read each file with the tool above. Write every tag, its text and its citation into a working table.\n3. Open every link a file points to. Add those tags.\n4. Fetch any data the sources name (feeds, APIs) and test each tag against it.\n5. Find disagreements between tags, and between tags and data. Move them to `conflicts`.\n6. Emit the JSON list. Keep a log of what you read and how.\n"
